# Code cleanup

Область: `$ARGUMENTS`. Если область пустая, спроси пользователя, что чистить. Весь репозиторий за раз не трогай.

## Жёсткие ограничения
- **Поведение не меняется.** Это рефакторинг, а не фикс багов. Найденные баги вынеси в отдельный список, не исправляй.
- **Денежную логику не трогаем:** `D()`, порядок операций внутри `prisma.$transaction`, `postTransaction`, распределение прибыли, снапшоты курса. Максимум можно переименовать локальную переменную.
- Не меняй публичные API-контракты (форму ответов роутов, типы в `src/types/index.ts`, маппинги в `src/api/mappers.ts`) без согласования.
- Тексты для пользователя остаются на русском и не меняются.
- Не трогай `prisma/migrations/`.

## Что искать
1. Неиспользуемые импорты, переменные, функции и экспорты (проверь Grep'ом по всему репо, включая `scripts/` и тесты).
2. Закомментированный код, устаревшие TODO, `console.log` и отладочный вывод.
3. Дублированная логика: одинаковые хелперы в нескольких страницах вынеси в `src/utils/` или `components/ui/`, на бэкенде в `server/src/common/`.
4. `any` и лишние `as`: замени на реальные типы, где это очевидно.
5. Слишком большие компоненты страниц: предложи (не делай без согласия) выделение подкомпонентов.
6. Мёртвые файлы, которые нигде не импортируются.

## Процесс
1. Сначала покажи план: список изменений по файлам. Жди подтверждения.
2. Делай изменения небольшими порциями, по одному типу чистки за раз.
3. После каждой порции запускай:
   - `npm run lint` (tsc --noEmit)
   - `npm test`
4. Если что-то упало, откати порцию и сообщи, не «чини» тесты.
5. В конце дай сводку: что удалено или упрощено (строк до/после), что оставлено и почему, найденные баги отдельным списком.

Не коммить без явной просьбы.
