# Security audit

Область: `$ARGUMENTS` (если пусто, то весь `server/src/` плюс конфиги деплоя).

Режим: **только отчёт**. Ничего не исправляй, пока пользователь не попросит.

## Что проверить

### 1. Аутентификация и сессии (`server/src/auth/`)
- JWT проверяется вместе с DB-backed `AuthSession`: logout и отзыв сессии действительно блокируют токен.
- `JWT_SECRET` не имеет дефолта в production; срок жизни токена разумный.
- Логин защищён rate limit (в `app.ts` и в `nginx/nginx.conf`), пароли хешируются (bcrypt/argon), нет перебора по логину.
- Сид не создаёт слабых паролей без `SEED_TEST_DATA=true`.

### 2. RBAC и изоляция магазинов (самое важное)
Пройди **каждый** `*.routes.ts` и inline-роуты в `app.ts`:
- У каждого мутирующего роута есть `requireRoles(...)` или эквивалентная проверка роли.
- Для `PARTNER` и `SELLER` `storeId` берётся из `req.user.storeId` (`enforceStoreScope` / `enforceBodyStoreScope`), а не из query/body.
- Доступ по id (`/:id`) проверяет, что запись принадлежит магазину пользователя (IDOR). Особенно продажи, возвраты, ремонты, переводы, расходы и инвойсы.
- Исключение для `isMainWarehouse` не открывает лишнего (только то, что нужно для переводов).
- Финансовые эндпоинты (owners, finance, payroll, капитал) недоступны продавцу.

### 3. WebSocket (`ws` gateway)
- Подключение требует валидный токен и активную сессию.
- `RealtimeSyncGateway.broadcast(..., { storeIds })` не рассылает данные чужих магазинов; payload не содержит лишних полей.

### 4. Ввод и база данных
- Нет `$queryRawUnsafe` / `$executeRawUnsafe` со строковой конкатенацией.
- Входные данные валидируются (типы, лимиты, денежные значения через `requirePositiveMoney` и т.п.).
- Mass assignment: `req.body` не передаётся в `prisma.*.create/update` целиком.

### 5. Ошибки и логирование
- Центральный обработчик не отдаёт stack trace, Prisma-ошибки или SQL клиенту.
- В логах нет паролей, токенов и полных JWT.

### 6. Конфигурация и секреты
- В git нет `.env` и ключей: `git ls-files | grep -i -E "\.env|key|secret|\.pem"`.
- CORS разрешает только `APP_URL`; CSP в `vercel.json` и заголовки безопасности (helmet или аналог) на месте.
- Idempotency: ключ привязан к пользователю, поэтому чужой ключ не вернёт чужой сохранённый ответ.

### 7. Зависимости
- Запусти `npm audit --omit=dev` и укажи только high/critical с реальным путём эксплуатации.

## Формат отчёта

Таблица находок по убыванию серьёзности:

| # | Серьёзность (Critical/High/Medium/Low) | Файл:строка | Проблема | Сценарий атаки | Рекомендация |

Затем коротко: что проверено и в порядке, что не удалось проверить. Каждая находка должна иметь конкретный сценарий эксплуатации; без него помечай её как «предположение».
